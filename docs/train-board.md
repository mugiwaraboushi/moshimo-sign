# 大岡山 発車標のデータ形式

`prototypes/train-board/` は、`data/timetable-ookayama.json` があればそれを読んで表示し、
無ければ**サンプルのダミー時刻表**で動く。実データを置けば、ページ側の変更なしで本物になる。

## ファイルの形

```json
{
  "updated": "2026-08-11T04:10:00.000Z",
  "station": "大岡山",
  "source": "公共交通オープンデータセンター（ODPT） https://www.odpt.org/",
  "lines": [
    {
      "name": "目黒線",
      "dirs": [
        { "to": "目黒",
          "weekday": [ { "t": "05:07", "type": "各停", "dest": "目黒" } ],
          "holiday": [ { "t": "05:11", "type": "各停", "dest": "目黒" } ] },
        { "to": "日吉", "weekday": [ ... ], "holiday": [ ... ] }
      ]
    },
    {
      "name": "大井町線",
      "dirs": [
        { "to": "大井町", "weekday": [ ... ], "holiday": [ ... ] },
        { "to": "溝の口", "weekday": [ ... ], "holiday": [ ... ] }
      ]
    }
  ]
}
```

- `lines` の順番がそのまま画面の段になる。**1本目が上段（目黒線）、2本目が下段（大井町線）**。
- `to` は方面（目黒方面／日吉方面…）。`dest` はその列車の行き先。`to` と違うときだけ画面に出る。
- `t` は `"HH:MM"`。`"24:05"` のような25時間制で書いてよい（読み込み時に 00:05 に畳む）。
- `type` は書いた文字がそのまま出る（各停 / 急行 など）。
- `weekday` / `holiday` で平日・土休日を分ける。**土日だけを土休日ダイヤとして扱う。祝日は未対応**
  （祝日も切り替えたいなら、ページ側に祝日リストを持たせる必要がある）。
- 昔の形式（`dirs[].trains`）もそのまま読める。その場合は曜日に関係なく同じダイヤになる。
- 終電後は日をまたいで翌朝の始発を「次発」として出す（表に「翌」と付く）。

## いま入っているデータ

`data/timetable-ookayama.json` は、**東急の「標準時刻表」PDF（2026年3月14日改正）を読み取ったもの**。
4方面（目黒線: 目黒方面・日吉方面／大井町線: 大井町方面・溝の口方面）の平日・土休日、あわせて約1,900本。

PDFの数字は文字ではなく図形で入っているのでテキスト抽出では取れない。
同じ数字は同じ形の図形で描かれる性質を使って機械的に読み取った。手順とスクリプトは
`tools/pdf-timetable/`。ダイヤ改正のときは、新しいPDFから同じ手順で作り直す。

- 種別は時刻の色で判定（目黒線: 赤=急行・黒=各停／大井町線: 赤=急行・緑と青=各停）
- 行先は時刻の上の小さな記号（西=西高島平、う=浦和美園、し=新横浜…）を読み取っている。
  記号のない列車はその方面の既定の行先（例: 日吉方面の無印は日吉）
- 検算として、時台が5,6,…,23,0の順であること・分が昇順であること、
  全1,887本に行先が付いていることを全4ファイルで確認済み

## 実データの入れ方

### 1. 公共交通オープンデータセンター（ODPT）から取る ← 仕掛けは用意済み

取得スクリプトとワークフローは入っている。**あとはキーを登録するだけ**。

- `scripts/fetch-timetable.mjs` … ODPTから取って `data/timetable-ookayama.json` を書く
- `.github/workflows/timetable.yml` … 毎日 04:10 JST に実行（手動実行もできる）

**管理者がやること（1回だけ）**

1. <https://developer.odpt.org/> で開発者登録し、**アクセストークン（コンシューマーキー）**をもらう。
2. リポジトリの Settings → Secrets and variables → Actions → New repository secret で
   名前 `ODPT_CONSUMER_KEY`、値にそのキーを登録する。**キーはリポジトリに書かない**。
3. Actions タブ →「大岡山の時刻表を取得（ODPT）」→ Run workflow で手動実行し、
   `data/timetable-ookayama.json` ができることを確認する。
4. 発車標のページを開く。サンプルの警告が消えて、出典が表示されれば成功。

**うまくいかないとき**

- 「駅時刻表が空でした」と出る場合、無料APIに東急の駅時刻表が含まれていない可能性がある。
  その場合はチャレンジ用APIのキーを取り、リポジトリ変数（Variables）に
  `ODPT_API_BASE = https://api-challenge.odpt.org/api/v4` を設定して再実行する。
- キーが未登録のあいだ、ワークフローは**何もせず正常終了**する（毎日赤くならない）。
- 手元で試すなら: `ODPT_CONSUMER_KEY=キー node scripts/fetch-timetable.mjs`

**出典表記**: ODPTのデータは出典の明示が求められる。スクリプトが `source` に書き込み、
ページはそれを画面に出す。消さないこと。

### 2. 駅の時刻表を手で入れる
平日・土休日 × 4方面ぶん。写真を送ってもらえれば起こせる。
一度入れればダイヤ改正まで使えるので、まずはこちらでも十分動く。

## 実機に出すときの注意

いまのファームウェアは**上段が固定文言・下段がスクロール**なので、この2段スクロールはそのままでは出せない。
実機に出すには、次のどちらかが要る。

- ファームウェアに「2段とも独立してスクロールする」モードを足す
- 上段を「目黒線 09:09 各停 目黒」のように4文字以内に切り詰めて固定表示にする（情報量は落ちる）
