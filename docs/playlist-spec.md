# playlist.json 仕様 (v1)

実機(ESP32)はGitHub Pages上の `playlist.json` を約60秒ごとに取得し、表示内容を更新する。
**このファイルをpushするだけで、もしもに設置された実機の表示が変わる。**
メンバーの「実機テスト」はこのファイルの更新で行う(ファームウェア自体の変更はファームウェア担当のみ)。

## フィールド

| キー | 型 | 意味 | 例 |
|---|---|---|---|
| `topText` | string | 上段の固定文言 (時計と交互表示) | `"営業中"` |
| `mode` | string | `"dual"`=2段 / `"scroll"`=1行スクロール / `"frames"`=ドット絵 | `"dual"` |
| `brightness` | int | 輝度 8-255 | `96` |
| `speed` | number | スクロール速度 dot/秒 (5-200) | `45` |
| `colorTop` | string | 上段の色 (RGB 16進6桁、#なし) | `"FF9C00"` |
| `colorScroll` | string | 下段スクロールの色。RGB 16進6桁、または特殊値 `"rainbow"` | `"FF9C00"` / `"rainbow"` |
| `messages` | string[] | スクロールで流す文言 (最大10件、◆で連結される) | |
| `frames` | object[] | ドット絵の静止画 (最大24枚)。`mode:"frames"` のときだけ使われる | |
| `commentsUrl` | string | イベントコメントの取得先 (v0.10〜)。空文字で取得を止める。詳細は下記 | `"https://script.google.com/macros/s/…/exec?action=text"` |
| `fwPing` | int | ファームウェアの版番号。実機より新しい値を書くと、その場で自己アップデートを実行する (v0.7〜)。手順: [`firmware-release.md`](firmware-release.md) | `9` |

- 省略したキーは現在値を維持する
- イベント時のコメント(`commentsUrl`経由)は `messages` の後ろに自動で連結される
- 上段は全角3〜4文字が収まる (64dot幅 ÷ 16dot/文字)
- 反映まで最大1〜2分 (取得間隔60秒 + CDNキャッシュ)

### レインボースクロール (v0.4〜)

`colorScroll` に `"rainbow"` を指定すると、下段のスクロールが虹色になる。

```json
{ "colorScroll": "rainbow" }
```

- **1文字ごとに色相が24°ずつ進む** ため、文字列に沿って虹のグラデーションがかかる
- 基準色相は時間で回転し、**約7.2秒で一周**する。文字は止まって見えても色は流れ続ける
- **対象は下段スクロールのみ。** 上段 (`colorTop`) は対象外で、指定した色のまま
- 周期・回転速度は固定 (v0.4ではパラメータ化していない)。細かく詰めたい場合は
  ビューア [`prototypes/rainbow/`](../prototypes/rainbow/) で試せる
- `"rainbow"` 以外の文字列は従来通りRGB 16進6桁として解釈される。
  16進として不正な値の場合は黒 (`0x0000`) になり、下段が消灯するので注意

> 設計メモ: 当初案は `colorMode` + `rainbowCycle` / `rainbowSpin` という新規フィールドだったが、
> 仕様の追加面積を最小にするため既存 `colorScroll` の特殊値として実装した。

### イベントコメント commentsUrl (v0.10〜)

イベント中に参加者のスマホから届いたコメントを、管理者が選別して実機に流すための取得先。
仕組みと手順は [`event-comments.md`](event-comments.md)。

```json
{ "commentsUrl": "https://script.google.com/macros/s/AKfy…/exec?action=text" }
```

- 実機は**15秒ごと**にこのURLを取りに行き、**1行1コメント**のプレーンテキストとして読む
  (最大20件。`messages` の後ろに ◆ で連結される)
- **イベントが終わったら `""` に戻す。** 取得が止まり、流れていたコメントも消える
- 受け付けるのは **`https://script.google.com/macros/` で始まるURLだけ。**
  それ以外は無視してシリアルに `commentsUrl rejected` と出る
  — `playlist.json` は公開されていて誰でも書けるため、実機が任意のホストを叩く状態にしない
  (`frames[].src` を相対パスだけに限っているのと同じ考え方)。
  他の置き場を使いたいときはファームウェアの `config.h` に `COMMENTS_URL` を書く
- 取得に失敗したときは**前回の内容がそのまま残る**(通信が切れた瞬間に表示が消えないように)
- 取得は**別タスクで行うのでスクロールは止まらない**。GASの応答は実測2〜3秒かかるため、
  表示側で待つと15秒ごとに固まって見える
- **止めたいときは `""` にする。** 取得タスクは `commentsUrl` が入って初めて起きるので、
  空にして push すれば次の再起動から動かない。この経路で不具合が出たときの退避路でもある
- `mode:"frames"` の間は画面に文字が出ないので、コメントも見えない

> v0.9以前は取得先が `config.h` 固定で、かつ**リダイレクトを追わなかった**。
> GASの `/exec` は `script.googleusercontent.com` への302を返すため、
> ファームウェアを書き換えて設定しても本文が取れない状態だった。

### ドット絵 frames (v0.5〜 / playlist v2.0)

お絵かきツール [`prototypes/draw/`](../prototypes/draw/) で描いた絵を、そのまま実機に出せる。
**v2.0は静止画のみ**(パラパラ動かすアニメーションは未対応)。

```json
{
  "mode": "frames",
  "frames": [
    { "d": "AAAAAcAAAAA…(342文字)", "color": "FF9C00", "hold": 8 }
  ]
}
```

| キー | 型 | 意味 | 既定 |
|---|---|---|---|
| `frames[].d` | string | 64×32のドット絵。base64url **342文字固定** | 必須 |
| `frames[].color` | string | 発光色。RGB 16進6桁 (`colorTop` と同じ形式) | `colorTop` の値 |
| `frames[].hold` | number | 表示秒数 (1〜60) | `8` |
| `frames[].holdMs` | number | 表示時間をミリ秒で指定 (20〜60000)。**`hold` より優先**。コマ送り用 (v2.1先行) | — |

#### 描いた絵を載せる手順

1. `prototypes/draw/` で絵を描く (**パネル構成は「64×32（1枚）」を選ぶ**)
2. 「playlist用をコピー」ボタンを押す → `{ "d": "…", "color": "…" }` がそのままコピーされる
3. それを `frames` の配列に貼り、`mode` を `"frames"` にして commit + push

URLから手で切り出す場合は、`#s=1&c=0&d=XXXX` の **`d=` 以降がそのまま `"d"` の値**になる。
`c=` は色番号なので、`color` には下の表の16進を書く:

| `c=` | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| `color` | `FF9C00` | `FF3B30` | `2EFF5E` | `27E0FF` | `FFFFFF` | `3B7BFF` |

#### 仕様の細部

- **データ形式**: 1ドット1bitのモノクロ。左上から行優先、1バイト＝8ドット、**MSBが左**。
  64×32 = 2048bit = 256バイト → base64url (パディング無し) で342文字
- **サイズは64×32固定**。draw の「64×16」「128×32」「192×32」(`s=0/2/3`) は v2.0では非対応
- `frames` が2枚以上あると、`hold` 秒ごとに次の絵へ切り替わり、最後まで行くと先頭に戻る
- `mode:"frames"` のときは**上段テキストも下段スクロールも出ない**(画がパネル全面)
- `mode` が `"dual"` / `"scroll"` のときは `frames` があっても無視される
- `d` の長さが342でない・base64として不正なフレームは**そのフレームだけ捨てて**残りを表示する
  (`messages` と違い、1枚壊れても画面が消えない)
- `mode:"frames"` なのに有効なフレームが0枚のときは `"dual"` にフォールバックする(黒画面にしない)
- 色はフレーム単位。1枚の絵の中で色を塗り分けることはできない(パネル全体の発光色として効く)
- `colorScroll` の `"rainbow"` は `frames` では使えない(v2.0では16進6桁のみ)

## 更新時の注意 (Claude向け・人間向け共通)

1. 変更前にJSONとして妥当か確認する (壊れたJSONは実機側で無視される=表示は前のまま)
2. 公共の場に出る文言なので、もしもの場に相応しい内容か確認する
3. 誰の依頼でいつ変えたかをコミットメッセージに残す。ただし**実名は書かない** — Discordの表示名かイニシャルを使う
   (例: `playlist: イベント告知を追加 (@discord表示名 の依頼)` / `playlist: 文言を修正 (M.S. の依頼)`)
   - このリポジトリは公開されるため、コミットログも誰でも読める。実名と発言の結びつきを残さない
   - 表示名と実名の対応が必要な場合は、git管理外の `CLAUDE.local.md` に控える

### v2.1 コマ送り再生 — クリップ参照

#### なぜコマを別ファイルにするか

1コマ = base64url 342文字。もしもくん相当（8秒 × 12fps = 96コマ）を1本ぶんベタ書きすると、
それだけで **約33KB**。8種類なら260KB を超える。`playlist.json` は実機が60秒ごとに
毎回まるごと取得するファイルなので、ここに置くと

- 文言をひと言変えるだけでも毎分260KBを取りに行くことになる
- 人間が `playlist.json` を開いて編集できなくなる（いま誰でも直せるのが利点）

したがって **コマ列は「クリップ」として別ファイルに置き、`playlist.json` からはパスで参照する**。
実機は再生するクリップだけを、必要になったときに1本ずつ取りに行く。

#### `frames[]` の書き方が2つになる

`frames` は「静止画の配列」から「**場面の配列**」になる。静止画とアニメを混ぜて並べられる。

```json
{
  "mode": "frames",
  "frames": [
    { "d": "AAAAAcAAAAA…(342文字)", "color": "FF9C00", "hold": 8 },
    { "src": "clips/moshimo-float.json", "loop": 3 },
    { "src": "clips/moshimo-trio.json", "dwell": 40, "color": "3B7BFF" }
  ]
}
```

| キー | 型 | 意味 | 既定 |
|---|---|---|---|
| `frames[].src` | string | クリップファイルのパス。`playlist.json` からの**相対パスのみ** | — |
| `frames[].loop` | int | 何周したら次の場面へ行くか (1〜99)。`0` = 次の場面へ行かず回り続ける | クリップの `loop` |
| `frames[].dwell` | number | 周回数ではなく秒数で切り上げたいときの上限秒 (5〜600)。`loop` と併記したら早いほう | なし |
| `frames[].color` | string | クリップの色を上書きする。RGB 16進6桁 | クリップの `color` |

- `d` と `src` の**両方を持つエントリは不正**。`d` があれば静止画として扱い `src` は無視する
- `src` は `clips/…` のような相対パスだけを許す。`http://` `https://` `../` で始まるものは捨てる
  （公開リポジトリの `playlist.json` に他所のURLを書かせないため。プロンプトインジェクション対策と同じ考え方）
- 取得に失敗した／中身が壊れているクリップは**その場面だけ飛ばす**（静止画のときと同じで、画面は消さない）

#### クリップファイルの形式 (`clips/<slug>.json`)

```json
{
  "v": 1,
  "w": 64,
  "h": 32,
  "fps": 12,
  "loop": 0,
  "color": "3B7BFF",
  "title": "もしもくん・ふわふわ",
  "frames": [
    "…342文字…",
    "…342文字…",
    { "d": "…342文字…", "ms": 2000, "color": "FF3B30" }
  ]
}
```

| キー | 型 | 意味 | 既定 |
|---|---|---|---|
| `v` | int | クリップ形式のバージョン。いまは `1` | 必須 |
| `w` / `h` | int | コマの大きさ。**v2.1では 64 / 32 のみ** | `64` / `32` |
| `fps` | number | 1秒あたりのコマ数 (0.5〜30)。1コマの表示時間 = `1000 / fps` ミリ秒 | `10` |
| `loop` | int | 既定の周回数。`0` = 無限 | `0` |
| `color` | string | 全コマの発光色。RGB 16進6桁 | `colorTop` の値 |
| `title` | string | 人間向けの名前。実機は無視する | — |
| `frames[]` | string \| object | コマ。文字列ならデータそのもの、オブジェクトなら下記 | 必須 |
| `frames[].d` | string | 64×32のドット絵。base64url 342文字固定（v2.0 と同じ） | 必須 |
| `frames[].ms` | number | このコマだけ表示時間を変える (20〜10000ミリ秒) | `1000 / fps` |
| `frames[].color` | string | このコマだけ色を変える | クリップの `color` |

- **データ形式は v2.0 の静止画とまったく同じ**（1bit・行優先・MSBが左・base64url 342文字）。
  つまり `prototypes/draw/` の `d=` も、もしもくんの書き出しも、そのまま1コマになる
- `d` が342文字でない／base64として不正なコマは**そのコマだけ捨てて**残りを再生する
- 有効なコマが0枚のクリップは、そのクリップごと捨てて次の場面へ行く
- **色はコマ単位**。1コマの中での塗り分けはできない。逆に言えば、
  日没のような「形はゆっくり・色が変わっていく」絵は `frames[].color` の変化で表現する

#### 大きさの上限（もしもくんアニメを基準にした予算）

| 項目 | 上限 | 根拠 |
|---|---|---|
| 1クリップのコマ数 | **96コマ** | 96 × 256B = 24,576B。実機に常駐させるのはこの1本ぶんだけ |
| 1クリップのファイルサイズ | **48KB** | 96コマぶんの base64 (約33KB) + 余白 |
| `frames[]` の場面数 | 8 | v2.0 の `MAX_FRAMES` を据え置き |
| 常駐するクリップ | 1本 | 次の場面のクリップは先読みしない（RAMが足りない） |

この上限に、いま作りたいものを当てはめるとこうなる:

| 作りたいもの | 収め方 | コマ数 |
|---|---|---|
| もしもくん「ふわふわ」等 8種 | 1周8秒 × 12fps を1本ずつ、8ファイル | 96 / 本 |
| 日没アニメ 40秒版 | `fps: 2` | 80 |
| 日没アニメ 2分版 | `fps: 0.5`、変化の速いところだけ `ms` で詰める | 60前後 |
| 紙芝居・似顔絵のパラパラ | 数コマ。`ms` で1枚ずつ好きな長さに | 〜10 |

上限を超えたクリップは、実機は**先頭から96コマだけ読んで残りを捨てる**（読み込み自体は失敗させない）。

#### 実機側の制約メモ（ファームウェア担当向け）

- **RAM**: いまグローバル変数が 57,432 / 327,680 B (17%)。ここに24KBの静的バッファを足す想定。
  ヒープは WiFi/TLS と HUB75 の DMA バッファが食うので、クリップ用は**動的確保せず静的に取る**ほうが安全
- **取得**: 33KB の JSON を `http.getString()` + DOM で丸ごと持つと、文字列とドキュメントで二重に載る。
  ストリームから読みながら 342文字ごとに 256B へデコードして捨てる形にしたい
- **切り替えの間**: クリップの取得に数秒かかる。その間は**最後のコマを出したまま**にして黒画面にしない。
  そのため場面の切り替えは `dwell` 30秒以上を推奨（もしもくんのWeb版は11秒ごとに切り替えているが、
  実機で同じ速さにすると取得待ちのほうが長くなる）
- **再取得の抑制**: 同じ `src` を再生し続ける間は取りに行かない。
  ETag / `If-None-Match` を見て、変わっていなければ読み直さない
- **60秒ポーリングとの関係**: `playlist.json` が更新されても、再生中のクリップは1周終わるまで切り替えない

### v2.2 `schedule` — 時刻で自動起動

日没アニメのための最小構成。**「この時刻になったらこのクリップを流し、終わったら元の表示に戻る」**だけ。

```json
{
  "topText": "営業中",
  "mode": "dual",
  "messages": ["ようこそ「もしも」へ"],
  "schedule": [
    { "id": "sunset", "at": "sunset", "offset": -3, "play": "clips/sunset.json", "loop": 1 },
    { "id": "open",   "at": "10:00",  "play": "clips/moshimo-float.json", "loop": 2 }
  ]
}
```

| キー | 型 | 意味 | 既定 |
|---|---|---|---|
| `schedule[].id` | string | エントリの名前。ログ用・「今日はもう流した」の記録キー | 配列の添字 |
| `schedule[].at` | string | 起動時刻。`"HH:MM"` (24時間・JST) または `"sunset"` / `"sunrise"` | 必須 |
| `schedule[].offset` | int | `at` からのずらし幅（分、-120〜120）。日没の3分前に始めたいなら `-3` | `0` |
| `schedule[].days` | string \| int[] | `"everyday"` / `"weekday"` / `"weekend"` / 曜日の配列 (0=日 … 6=土) | `"everyday"` |
| `schedule[].play` | string | 流すクリップのパス。`frames[].src` と同じ規則（相対パスのみ） | 必須 |
| `schedule[].loop` | int | 何周流すか (1〜99)。`0` は使えない（戻れなくなるため） | `1` |
| `schedule[].window` | int | 取りこぼしを許す幅（分、0〜60）。この幅の中なら遅れて起動してよい | `10` |

#### 発火のきまり

1. **1日1回**。同じ `id` は同じ日に二度は流さない（`prototypes/sunset/` の `firedFor` と同じ考え方）
2. **時刻が信用できないときは何もしない**。NTP同期前（`time()` が 2020-01-01 より前）は
   `schedule` を丸ごと無視する。時計がずれたまま真夜中に日没アニメが流れるほうが困る
3. **取りこぼし**: 起動時刻を過ぎていても `window` 分以内ならその場で流す。
   それより遅れていたら今日はあきらめて翌日に回す（電源断・WiFi断からの復帰を想定）
4. **重なったとき**: 先に始まったものを最後まで流す。再生中に来た別のエントリは今日はスキップ。
   同時刻なら配列の**先にあるほうが勝つ**
5. **終わったら**: 元の `mode` / `topText` / `messages` の表示にそのまま戻る。
   `schedule` は「割り込んで流す」だけで、`playlist.json` の他のフィールドは書き換えない
6. 再生中に `playlist.json` が更新されても、割り込み再生は最後まで流し切ってから反映する

#### 日の入り・日の出の時刻

- **通信しない。** 実機のNTP時刻と緯度経度から計算する。
  [`prototypes/sunset/`](../prototypes/sunset/) の `sunsetOn()` がそのまま移植できる
  （2000年紀元のユリウス日 + 太陽赤緯。天文薄明ではなく視太陽の -0.833° を採用済み）
- 緯度経度は**ファームウェアの `config.h`** に置く (`SITE_LAT` / `SITE_LON`、既定は大岡山)。
  `playlist.json` からは上書きしない — 設置場所の座標は表示内容ではないので、
  誰でも編集できるファイルに置く必要がない
- 日の入り時刻は日々変わるので、実機は**1日1回（0時すぎ）だけ計算し直す**

### さらに先 (v2.3以降)

- `frames` の 128×32 / 192×32 対応（パネルを増設したとき）。クリップの `w` / `h` は
  そのための場所として先に空けてある

- クリップの差分圧縮。コマ間の差分は小さいので、96コマの上限を上げたくなったらここを削る
