# 東急の標準時刻表PDFから `data/timetable-ookayama.json` を作る

東急の駅時刻表PDFは、数字も行先の記号も**文字ではなく図形（パス）**で入っている。
テキスト抽出では1文字も取れないので、次の手順で読み取った。

> 同じ数字は**まったく同じ形のパス**で描かれている、という性質を使う。
> 形ごとにまとめて「この形は何の数字か」を人間が10回だけ確認すれば、
> あとは機械的に全部の時刻に展開できる。目視で1,000個以上を書き写す必要はない。
> 行先の記号（かな・漢字）は座標が1つずつ微妙に違うので、
> こちらは形の指紋（8×8の点密度）の近さでまとめている。

## 使い方（ダイヤ改正のたびに1回）

準備: このディレクトリで `npm i pdfjs-dist` （pdf.js だけ使う。リポジトリには入れない）

1. PDFを `tt/` に置く。ファイル名は方面ごとに分かる名前にする
   （例: `mg06_1.pdf`=目黒線 目黒方面, `mg06_2.pdf`=目黒線 日吉方面,
   `om08_1.pdf`=大井町線 大井町方面, `om08_2.pdf`=大井町線 溝の口方面）

2. **形の抽出**: `node 1-paths.mjs tt/mg06_1.pdf`
   → `tt/mg06_1.shapes.json`（位置・色・形のキー・形の指紋）ができる

3. **行先記号のまとめ**: `node 2-marks.mjs tt/mg06_1.pdf`
   → 時刻の上の小さな字を指紋の近さでまとめて `tt/mg06_1.marks.json` に保存

4. **数字と記号の対応づけ**: `samples.html` をローカルサーバ越しに開き、
   形ごとの代表を並べた一覧を見て次を作る。**ここだけ人間の目視**。
   - `digits.json`（分の数字）/ `digits-hour.json`（時台の数字） … `?f=tt/mg06_1.pdf&s=tt/samples.json`
   - `dests.json`（記号→行先。PDFの「行先の凡例」を見て決める） … `?f=tt/mg06_1.pdf&s=tt/mg06_1.marksample.json`

   ダイヤ改正でフォントが変わらなければ、前回のものをそのまま使える。

5. **組み立て**: `node 3-assemble.mjs tt/mg06_1.pdf`
   → 時台ごとの分に組み立て、各列車に行先を付けて `tt/mg06_1.rows.json` に保存。
   同時に**時台が5,6,…,23,0の順に並んでいるか**と**分が昇順か**を検算して表示する。
   ここで警告が出たら、そのまま使わずに原因を見ること。

6. **JSON化**: `node 4-build.mjs "2026-08-11T11:10:00+09:00"`
   → `tt/timetable-ookayama.json`。これを `data/` にコピーする。

## 種別と行先の判定

**種別**は時刻の色で決まる（PDFの凡例どおり）。

- 目黒線: 赤=急行 / 黒=各停
- 大井町線: 赤=急行 / 緑・青=各駅停車（緑と青は編成の違いで、どちらも各停）

**行先**は時刻の上の小さな記号。`dests.json` に「まとまりの番号 → 行先」と
「記号がないときの既定の行先」を書く。2026年3月改正版では次のとおり。

| 方面 | 記号 |
|---|---|
| 目黒線 目黒方面 | 西=西高島平 / う=浦和美園 / 赤=赤羽岩淵 / 高=高島平 / は=鳩ヶ谷 / 目=目黒 / 王=王子神谷 / こ=駒込（無印なし） |
| 目黒線 日吉方面 | 無印=日吉 / し=新横浜 / 海=海老名 / 武=武蔵小杉 / 湘=湘南台 / 谷=西谷 / 大=大和 / 奥=奥沢 |
| 大井町線 大井町方面 | 無印=大井町（記号なし） |
| 大井町線 溝の口方面 | 無印=溝の口 / 林=中央林間 / 長=長津田 / さ=鷺沼 / 二=二子玉川 |

オレンジの「Q」はQ SEAT車両の印で行先ではない。●は当駅始発の印。どちらも行先には使わない。

## 注意

- これは時刻表であって運行情報ではない。遅延・運休は分からない。
- 正しさは4本のPDFすべてで検算（時台の連番・分の昇順・行先の欠けなし）を通していて、
  さらに数行を目視で突き合わせている。それでも公式の時刻表が正である。
